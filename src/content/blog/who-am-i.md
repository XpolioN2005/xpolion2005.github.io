Hey, I'm **Darsan Ghosh**, though I usually go by **XpolioN** online.

I'm a third-year B.Tech Computer Science and Engineering student at **Techno India University, West Bengal**. Most of my time outside college goes into building software, experimenting with game development, and going down technical rabbit holes that probably started with a simple question.

I've been meaning to start writing devlogs for a while, and this seemed like a good place to start.

## How I Got Into Game Development

My journey into game development started with **Python and Pygame**.

I started with small projects and, in the process, learned the basics of game loops, input handling, drawing, and making different pieces of code work together to create something interactive.

Eventually, I wanted to build more than what I could comfortably do with those small projects, which led me to **Godot and GDScript**.

Godot introduced me to a much larger set of concepts. Scenes, nodes, physics, animation, resources, rendering, and all the other systems that come with a game engine.

The interesting part was that learning to use an engine eventually made me more curious about how the engine itself works.

## Where My Interests Went

This is probably the part that interests me the most.

I don't just want to learn how to use a game engine. I want to understand what is happening underneath it.

I'm particularly interested in **game engine architecture and graphics programming**.

For example, I want to understand how a game engine organizes and updates its world, how data moves through different systems, and how those systems eventually produce a frame on the screen.

That naturally leads into **rendering**.

I'm interested in things like rendering pipelines, GPU and CPU workloads, shaders, resource management, and the decisions that affect how efficiently a game can produce frames.

I'm also interested in **performance and low-level programming**. I like understanding why something is slow rather than simply finding a way to make the problem disappear.

That means I'm interested in areas such as memory, data layout, CPU and GPU workloads, profiling, and the tradeoffs involved in different implementations.

I don't have all of this figured out yet, and that's exactly why I want to explore it.

There is a lot I still need to learn before I can confidently say I understand these systems. For now, I'm interested in digging deeper and seeing where that takes me.

## It's Not Just Games

Game development is my main technical and creative interest, but I work on other kinds of software too.

Depending on what I'm building, I use languages such as **Python, GDScript, C, C++, Rust, Java, C#, and JavaScript**.

I've also worked with technologies such as **React, Astro, and Flutter**.

This website itself is built from scratch using **Astro**.

I enjoy working across different areas because the problems are often more connected than they initially seem. Something I learn while working on a game can turn out to be useful in another software project, and the opposite can happen too.

## Why Start a Devlog?

I don't want this site to only show finished projects.

A finished project tells you what I made, but it doesn't necessarily tell you how I got there.

It doesn't show the bugs that took hours to understand, the ideas that didn't work, or the implementation that looked good at first and turned out to be a terrible idea later.

I want to document some of that process.

These devlogs will be where I write about what I'm building, what I'm learning, problems I run into, experiments I try, and things I find interesting.

Some posts will probably be technical. Others might be more about a project or an idea I'm exploring.

## You'll Hear My Opinions Too

These aren't going to be completely neutral technical articles.

**You'll see my opinions here.**

If I like a tool, I'll say why I like it.

If I think something is unnecessarily complicated, I'll probably complain about it.

If I disagree with an approach that seems popular, I'll explain why.

And I won't always be right.

My opinions are going to change as I learn more, and I'm completely fine with that. A devlog is a record of what I thought and understood at a particular point in time, not a claim that I've figured everything out.

So if I change my mind about something later, that's part of the journey too.

## What's Ahead

I want to use this devlog to document my progress as I explore the more technical side of game development.

That means learning more about **game engine architecture, rendering, graphics programming, performance, and low-level systems**, while continuing to build actual projects along the way.

I'll probably make things that work, things that don't work, and a few things that I eventually decide were a bad idea.

Hopefully, I'll learn something from all of them.

Anyway, that's enough of an introduction.

**Let's see what I can build.**
